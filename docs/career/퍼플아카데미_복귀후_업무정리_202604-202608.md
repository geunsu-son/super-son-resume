## 0. 이력서 에이전트 사용 가이드

이 문서는 **채용용 이력서/경력기술서를 쓰는 에이전트**가 읽기 쉽게 구조화했다.

| 섹션 | 용도 |
|------|------|
| §1 한 줄 포지셔닝 | 요약 문단·헤드라인 후보 |
| §2 스킬·스택 | Skills / Tools 섹션 |
| §3 역할별 하이라이트 | 이력서 bullet 초안 (이미 STAR 형태로 정리) |
| §4~7 상세 작업 카탈로그 | 면접 깊이·프로젝트 서술용 디테일 |
| §8 AI 활용 역량 | “AI로 업무를 설계·운영한다” 어필 근거 |
| §9 타임라인 | 월별 스토리라인 |
| §10 경로 인덱스 | 산출물 원본 위치 (검증·인용) |

**권장 추출 규칙**

1. 역할별로 §3에서 3~6개 bullet만 고른다 (전체 나열 금지).
2. 기술 키워드는 §2 + 각 작업의 `스택` 필드를 합친다.
3. “무엇을 만들었는지”보다 **운영 자동화·데이터 정합·의사결정 근거**를 우선한다.
4. AI 어필은 §8을 단독 섹션 또는 “업무 방식” 한 단락으로 쓴다.
5. 민감 정보(원번 대량 목록, `.env`, 내부 IP/공유폴더 경로 세부)는 이력서에 넣지 않는다.

## 1. 한 줄 포지셔닝

퍼플아카데미 LMS·Inner DB를 중심으로 **월간 ETL/정기업무 파이프라인**, **진단·도서·퀴즈 운영 자동화**, **추천도서 정책 검증·임원 보고**, **내부 Streamlit 조회 앱**, **Cursor 멀티에이전트 운영 OS**를 설계·구현한 **데이터 엔지니어 / 데이터 분석가 / RPA·AI 업무자동화 전문가**.

## 3. 역할별 이력서 하이라이트 (바로 쓸 bullet)

### 3.1 데이터 분석가 (`DA`)

- **추천도서 2.0 정책 검증**: Lexile 캡(+150)·AR vs Lexile 슬롯 백테스트·MG 개방조건 비교 분석을 수행하고, 임원/그룹웨어용 HTML 보고서로 AR 슬롯 유지 + Lexile 캡 역할 권고를 도출.
- **입학·상담 인사이트**: 입학예약(42개월+) 리드 집계와 입학상담(`tbl_consultings`) LLM 니즈 라벨링·페르소나 분석을 그룹웨어 brief/executive HTML로 통합 보고.
- **학습 효과·품질 분석**: 얼리버드 A/B 관측 비교, 리딩특공대 단계별 SR/Lexile 성장, Assessment 문항 정답률·레벨 편향, FutureScribe 라이팅 점수 분포, 행성별 SR/Lexile 추이 파이프라인 구축.
- **환산·도메인 모델링**: SR↔Lexile 경험적 환산표(isotonic/PAVA 개념 포함)·BL 확장 자료를 추천 엔진 reference로 연결.

### 3.2 데이터 엔지니어 (`DE`)

- **월간 리딩 통합 파이프라인**: 리딩데이터 적재 → 3개월 요약 xlsx → 나의서재(`tbl_recommend_user_books`) upsert를 `run_monthly.py` 한 회차로 오케스트레이션.
- **종합성취도·목표WC ETL**: 영역별/종합 점수 배치 적재와 익월 목표 WC 산출(일할·신기수 규칙·Gate)을 `.py` 승격·매뉴얼화.
- **데이터 정합 마이그레이션**: 이반 원생 `class_id` 이관(preview→파일럿→주간 스케줄), 레거시 `class_students` 이관, 도서 KPLBN 오매칭 1권 단위 library→prd 전파(당월 나의서재 보호).
- **콘텐츠 마스터 유지보수**: IXL permacode 크롤·스킬 메타 반영, 퀴즈 보기/`correctIndex` 오류 재채점, AR Book Finder 신규 등록·표지 S3 파이프라인.
- **내부 데이터 앱**: Streamlit 멀티페이지(목표WC, 완료율, 이반이관, 승급배정, 진단 응시, 리딩미션, 학습링크, Synology 분배)로 운영팀 셀프서비스 조회·실행 UI 제공.

### 3.3 RPA 전문가 (`RPA`)

- **르네상스러닝 자동화**: 원생명단 크롤 EXE, ReadingProgram 관리 UI(클래스/어사인/**Grade 일괄 변경**), 로그인 페이지 변경 대응·ChromeDriver 장애 복구.
- **맞춤 커리큘럼 진단 운영 RPA**: IXL 어사인 → 결과 수집 → 권고알림(Stream C 스케줄) → 결과지 PDF·S3·문서함 배포(Stream D) End-to-End.
- **제주 리딩센터 월간 리포트**: DB 대상자 동기화 → HTML/PDF 일괄 생성 Skill화.
- **운영 배치·파일 분배**: 도서 AR 미매칭 일 08:00 스케줄, 이반 주간 이관 스케줄, Synology 반별 엑셀 all-or-nothing 분배.

### 3.4 AI 활용·에이전트 설계 (`AI`) — 차별화 포인트

- Cursor를 **데이터팀 운영 OS**로 설계: Agent Router + 도메인 Rules/Skills + db-docs Context Index로 “질문 → 전문 에이전트 → Gate 승인 → 커밋/PR/머지” 표준화.
- 정기업무·마이그레이션·도서수정·IXL·제주리포트 등을 **Skill/매뉴얼 페어**로 만들어 에이전트가 재현 가능하게 실행.
- 분석은 `data-analysis-specialist` / `analysis-report-html`(brief·executive·counseling)로 **가설→검증→쉬운 해석→보고**까지 에이전트 워크플로화.
- 약 376개 채팅 세션에서 단건 CS(퀴즈 정답 수정, 도서 KPLBN, 결과지 재배포)부터 대형 기획(추천엔진 MVP/TS)까지 AI와 페어 프로그래밍·운영.
